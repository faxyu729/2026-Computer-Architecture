## 驗證結果摘要

依據以下組譯驗證指令（使用 GNU Binutils 2.47，以 `rv32im` / `ilp32` 組態）：

```bash
riscv64-elf-as -march=rv32im -mabi=ilp32 insn-test.S -o insn-test.o
riscv64-elf-objdump -d insn-test.o > objdump.txt
```

三個範例之手算機器碼與反組譯機器碼比對結果：

1. **`bitrev a0, a0`（邊界值）**：
   - 機器碼：`0x0005050B`
   - 反組譯：`0005050b`（一致 ✓）
   - 效果：`a0: 0x00000001 → 0x80000000`
2. **`bitrev t0, a1`**：
   - 機器碼：`0x0005828B`
   - 反組譯：`0005828b`（一致 ✓）
   - 效果：`a1: 0x0000000F → t0: 0xF0000000`
3. **`bitrev s1, s2`**：
   - 機器碼：`0x0009048B`
   - 反組譯：`0009048b`（一致 ✓）
   - 效果：`s2: 0x12345678 → s1: 0x1E6A2C48`

```markdown
### 2.2 指令編碼與欄位說明

`BITREV` 採用標準 RISC-V 32-bit R-type 指令格式，操作碼分配於 `custom-0` 空間：

 31      25 24   20 19   15 14  12 11    7 6       0
+----------+-------+-------+------+-------+---------+
|  funct7  |  rs2  |  rs1  |funct3|  rd   | opcode  |
+----------+-------+-------+------+-------+---------+
   7 bits   5 bits  5 bits  3 bits 5 bits   7 bits

| 欄位名稱 | 位元範圍 | 寬度 | 固定值 / 意義 |
|:---|:---:|:---:|:---|
| **funct7** | `[31:25]` | 7 bits | `0000000`（教師分配功能碼） |
| **rs2** | `[24:20]` | 5 bits | `00000`（一元運算未使用，固定填 `x0`） |
| **rs1** | `[19:15]` | 5 bits | 來源暫存器編號（5-bit） |
| **funct3** | `[14:12]` | 3 bits | `000`（教師分配功能碼） |
| **rd** | `[11:7]` | 5 bits | 目的暫存器編號（5-bit） |
| **opcode** | `[6:0]` | 7 bits | `0001011`（`custom-0`，0x0B） |

硬體特性：純內部導線交叉連接，無邏輯閘延遲，只有導線延遲。

### 2.3 機器碼組譯公式

各欄位依其硬體解碼位移量進行位元運算合成 32-bit 機器碼：

```c
機器碼 = (funct7 << 25) | (rs2 << 20) | (rs1 << 15) | (funct3 << 12) | (rd << 7) | opcode
```
```

### 【供貼入 CP3.md 第 3 節（結果與分析）】

```markdown
### 3.1 範例說明 (3 個範例含 1 個邊界值)

各範例欄位位元分佈參見圖表 [figures/cp3_encoding_fields.png](figures/cp3_encoding_fields.png)。

#### 範例 1：`bitrev a0, a0`（邊界值）
- **組譯語法**：`bitrev a0, a0`（`rd`=a0/x10, `rs1`=a0/x10, `rs2`=x0）
- **欄位二進位**：
  - `funct7`=0000000, `rs2`=00000, `rs1`=01010, `funct3`=000, `rd`=01010, `opcode`=0001011
  - 32-bit 分組：`0000 0000 0000 0101 0000 0101 0000 1011`
- **機器碼手算推導**：
  - `(0x00 << 25) | (0x00 << 20) | (10 << 15) | (0x0 << 12) | (10 << 7) | 0x0B`
  - `= 0x00050000 | 0x00000500 | 0x0B = 0x0005050B`
- **執行前後暫存器數值**：
  - 執行前：`a0` = `0x00000001`
  - 執行後：`a0` = `0x80000000`
- **組譯驗證**：GNU as `.insn r 0x0B, 0, 0, a0, a0, x0` 產出機器碼 `0x0005050B`（吻合 ✓）。
- **說明**：最低位 1 反轉至最高位，為 LSB → MSB 極限邊界值。

#### 範例 2：`bitrev t0, a1`
- **組譯語法**：`bitrev t0, a1`（`rd`=t0/x5, `rs1`=a1/x11, `rs2`=x0）
- **欄位二進位**：
  - `funct7`=0000000, `rs2`=00000, `rs1`=01011, `funct3`=000, `rd`=00101, `opcode`=0001011
  - 32-bit 分組：`0000 0000 0000 0101 1000 0010 1000 1011`
- **機器碼手算推導**：
  - `(0x00 << 25) | (0x00 << 20) | (11 << 15) | (0x0 << 12) | (5 << 7) | 0x0B`
  - `= 0x00058000 | 0x00000280 | 0x0B = 0x0005828B`
- **執行前後暫存器數值**：
  - 執行前：`a1` = `0x0000000F`
  - 執行後：`t0` = `0xF0000000`
- **組譯驗證**：GNU as `.insn r 0x0B, 0, 0, t0, a1, x0` 產出機器碼 `0x0005828B`（吻合 ✓）。

#### 範例 3：`bitrev s1, s2`
- **組譯語法**：`bitrev s1, s2`（`rd`=s1/x9, `rs1`=s2/x18, `rs2`=x0）
- **欄位二進位**：
  - `funct7`=0000000, `rs2`=00000, `rs1`=10010, `funct3`=000, `rd`=01001, `opcode`=0001011
  - 32-bit 分組：`0000 0000 0000 1001 0000 0100 1000 1011`
- **機器碼手算推導**：
  - `(0x00 << 25) | (0x00 << 20) | (18 << 15) | (0x0 << 12) | (9 << 7) | 0x0B`
  - `= 0x00090000 | 0x00000480 | 0x0B = 0x0009048B`
- **執行前後暫存器數值**：
  - 執行前：`s2` = `0x12345678`
  - 執行後：`s1` = `0x1E6A2C48`
- **組譯驗證**：GNU as `.insn r 0x0B, 0, 0, s1, s2, x0` 產出機器碼 `0x0009048B`（吻合 ✓）。
```

> **【供組員 C 與 D 參考：§3.2 指令數比較正確數據】**
> （依 HOMEWORK §5.4 規定，需明確標明計數方式與工具）
> - **計數方式**：靜態指令數（Static instruction count）與動態指令數（Dynamic instruction count）。
> - **量測工具**：GNU Binutils 2.47 `objdump`（靜態）、Ripes `v2.2.6`（動態模擬）。
> - **單次位元反轉指令**：
>   - RV32IM baseline 核心（含 `ret`）：**36 條**
>   - 自訂指令 `bitrev`（單條指令嵌入）：**1 條**
>   - **減少比例**：$\frac{36 - 1}{36} = \mathbf{97.2\%}$
> - **若以獨立函式包裝形式（含 `ret`）**：
>   - 36 條 → 2 條（`bitrev a0, a0` + `ret`）
>   - **減少比例**：$\frac{36 - 2}{36} = \mathbf{94.4\%}$
